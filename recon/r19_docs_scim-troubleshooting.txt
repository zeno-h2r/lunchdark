"Developer\nOn this page\nOwner restrictions\nDeactivated users\nRole keys\nEmail uniqueness\nField validation\nOkta compatibility\nExtension schema declaration\nYour account\nAccount security\nSingle sign-on\nEnable SCIM provisioning\nSCIM API constraints and troubleshooting\nThis topic explains constraints on the LaunchDarkly System for Cross-domain Identity Management (SCIM) API and how to troubleshoot common problems.\n​\nOwner restrictions\nOwner restrictions include:\nYou cannot create users with the \"owner\" role. The API returns a 400 error: “Cannot create an owner.”\nAny attempt to update an existing owner’s role using SCIM is silently ignored. No error is returned.\nYou cannot deactivate an owner. The API returns a 400 error: “Cannot deactivate an owner.”\nOnly one owner is allowed per account.\n​\nDeactivated users\nYou cannot update attributes (name, role, and so forth) on a user who is currently deactivated (active: false). You must reactivate them first or simultaneously with the update.\n​\nRole keys\nWhen assigning custom roles, you must use the role key, and not the human-readable name or ID. Custom roles must exist in the account before they can be assigned.\n​\nEmail uniqueness\nEmail addresses must be unique within an account. If you attempt to provision a user with an email that already exists, you will receive a 409 Conflict error.\n​\nField validation\nField validation includes:\ngivenName and familyName must be 256 characters or fewer each.\nEmail addresses must use a valid format.\nRole values must be \"reader\", \"writer\", \"admin\", or \"noAccess\".\n​\nOkta compatibility\nFor Okta requests (identified by User-Agent header starting with okta), the customRole string field is not included in responses. Only customRolesArray is returned.\n​\nExtension schema declaration\nThe LaunchDarkly implementation is lenient and will accept root-level extension attributes (role, customRole, customRolesArray) even if the extension schema is not declared in the schemas array. However, for strict SCIM 2.0 compliance, include urn:ietf:params:scim:schemas:extension:launchdarkly:2.0:User in the schemas array when using these attributes.\nSCIM API error responses\nPrevious\nEnable SSO\nNext"
